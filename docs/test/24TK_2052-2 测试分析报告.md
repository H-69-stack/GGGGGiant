## 5. 过程中出现的问题

### 5.1 插件返回「独立 QA：FAIL」与权威文件矛盾（主要问题）

- 现象：`analyze` 工具返回文本 `CAD 管件分析完成；独立 QA：FAIL`，但磁盘上的 `acceptance.json`（jobs 目录与结果包内副本哈希一致）为 `PASS`，44 项检查全部通过，`mandatory_pass=true`；用私有运行时重放 validator 退出码 0，同样 PASS。
- 排查路径：
  1. 读 jobs 目录权威 acceptance.json：PASS，0 失败项
  2. 对比结果包内副本哈希：一致（`536027D7…3AA4`）
  3. 重放 `validate_outputs.py`：exit 0，status PASS
  4. 读插件源码 `tools/analyze.js`：FAIL/PASS 判定依据是 validator 返回的 **stdout payload**（`parseLastJson`），而非磁盘文件
  5. 读 `lib/runtime.js` 的 `parseLastJson`：从 stdout 按行分割，**从后往前找第一个能 JSON.parse 的单行**
  6. 捕获 validator 完整 stdout（1119 行多行缩进 JSON），逐行扫描可解析行，复刻解析逻辑：命中第 1047 行孤立数字 `5`
- 根因：validator 输出的是 `json.dumps(indent=2)` 多行 JSON；`parseLastJson` 逐行尝试解析，多行 JSON 中某一行恰好是独立的合法 JSON 值（`fixed-point-iterations` 检查里迭代数组的元素 `5`），被当作完整 payload 吞掉，导致 `acceptance.status` 取不到、工具判定为 FAIL，`check_count` 也为 null。
- 影响面：所有正常 PASS 的分析都可能显示 FAIL，属于工具层显示/判定缺陷，不影响数据本身。

### 5.2 运行时首次 bootstrap 的网络依赖（历史问题，本次已解决）

- 昨晚曾因直连海外下载源不通导致运行时初始化失败；本次在全局代理（yepfast 监听 7892）已开启的前提下，bootstrap 一次成功。
- 经验：此类插件首次运行时需确保代理/全局模式可达海外源。

### 5.3 排查中的环境小坑

- session 文件 fileId 直读报 not found，需从磁盘 `plugin-data/…/jobs` 定位实体文件
- jobs 目录受沙箱写保护，比对哈希/重放 validator 需提升权限执行
- PowerShell 重定向 stdout 默认 UTF-16 编码，后续用 Python 读取时需按 BOM 判断解码

## 6. 后续改进建议

### 6.1 插件层（优先级高）

1. **修复 `parseLastJson`（`lib/runtime.js`）**：改为「从后往前找到第一个以 `{`/`[` 开头并在后续行闭合的完整 JSON」，或用字符串括号配平扫描；或要求 validator 输出单行 compact JSON（`json.dumps(separators=(",", ":"))`）。
2. **工具判定以磁盘为准**：`tools/analyze.js` 在 `analysisText` 前重新读 `jobDir/acceptance.json`，以写盘权威文件判定 PASS/FAIL，stdout payload 仅作参考。
3. **补回归测试**：为 `parseLastJson` 增加「多行 JSON + 中间含孤立数字行」的用例，防止回归。

### 6.2 流程层

4. 遇到「插件返回 FAIL」时，先读权威 `acceptance.json` 确认是否真失败，再决定是否深挖；把这一步写进常见问题 SOP。
5. 结果交付时明确标注「CAD 名义几何，不等于制造后实测壁厚」，后续量产前需抽测验证。

### 6.3 后续迭代方向

6. 可将该管件的中心形线与壁厚场直接喂给下游 Giant 工艺规划/模具设计流程（同源 STEP 与 PASS 包），验证端到端链路。
7. 建议对扩口段（外周长 58.8 → 97.6 mm）单独做一节密度更高的壁厚采样，确认 1.70 mm 加厚在扩口区的均匀性。
